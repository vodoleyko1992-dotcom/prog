# Warlock → Arcana Lord: план боевого ИИ до 78 уровня

**Статус:** проект тактики. Только подтверждённые умения текущего персонажа используются в действующем боевом цикле; всё будущее перечислено как ориентир по Lineage II Interlude, а **не как установленный факт о L2WAP**.

## Достоверные данные из L2WAP (журнал 09.10.2026)

Персонаж `Warlock` по имени, текущая **профессия `human_mage`**, уровень 10. На панели: `Атака`, `Wind Strike` (`l2_1177`), `Heal`, `Зілля мани`, `Зілля слабкого зцілення`, `Благословенний заряд духу` (Blessed Spiritshot). В окне магистра наблюдаются также доступные/предстоящие `Ice Bolt`, `Curse Poison`, `Cure Poison`, `Shield`, `Might`, пассивные `Anti Magic`, `Weapon Mastery`, `Armor Mastery`.

Сервер возвращал HTTP 400 `skill_cooldown` с `blockedBy=global`, `globalCooldownUntilMs` и `serverNowMs`. Эти данные — основной источник времени повторного действия. Были также наблюдения собственного отката Wind Strike. Обновление v7.1.14 считывает глобальный таймер через `/game/battle/sync`.

## Архитектура Warlock AI

1. **Character/Profile:** `human_mage` / `human_wizard` / `warlock` / `arcana_lord` — проверять профессию персонажа, не имя героя. Активировать только доступные умения на панели/из игрового каталога.
2. **CooldownManager:** отдельные общая пауза (`globalCooldownUntilMs`) и КД каждого навыка. На HTTP 400 `blockedBy=global` ждать только глобальную паузу; не учить ложный КД конкретного навыка. При смене боя — обновление идентификатора противника.
3. **SummonManager (отложенная интеграция):** `pet=none/summoning/active/dead/unknown`; проверять подтверждение призыва по серверу и активного питомца, лимит повторов и реальные остатки кристаллов. В бою не кастовать призыв без подтверждённой игровой возможности.
4. **PetCombat (отложенная интеграция):** отдельная атака питомца, цель синхронизирована с целью игрока. Не использовать команды, пока не наблюдены реальные селекторы/API L2WAP.
5. **PetSupport (отложенная интеграция):** Servitor Heal при реальной потере HP; Servitor Recharge — при доказанном дефиците MP питомца; Cure/Blessing — по конкретному дебаффу. Нет питомца — все действия заблокированы.
6. **CubicManager (отложенная интеграция):** призвать только если отсутствует нужный кубик, хватает реагентов и время жизни окупит стоимость; избегать повторной покупки/каста без подтверждения.
7. **ResourceManager:** резерв MP для Heal, запас кристаллов и аден, порог максимального расхода ресурсов на один бой/час, проверка полученного EXP с учётом возможной доли питомца.
8. **RaidPlanner:** заранее усилить питомца и кубики, оценивать DPS игрока + питомца отдельно, не считать незафиксированный урон питомца; после серии спецударов поднимать порог лечения питомца и проверять допустимость продолжения.

## Решение для боевой ротации сейчас (уровень 10)

- Атакующие скиллы: `Wind Strike` и только реально изученные другие прямые атаки.
- Применить `Heal` при опасном HP, иначе нет бессмысленного расходования MP.
- `Blessed Spiritshot` — через наблюдаемый слот, без использования физического Soulshot.
- При GCD читать серверный `globalCooldownUntilMs`, ждать готовность, затем выбирать удар; при собственном КД Wind Strike — обычная атака либо другой изученный боевой навык.
- Нет атакующей панели сразу после загрузки — краткое ожидание и повтор чтения, **не глобальная остановка бота**.
- Не включать `Summon*`, `Servitor*`, `*Cubic*`, `Transfer Pain`, `Final Servitor`, `Warrior Servitor` в список атак или `Heal` героя.

## Что понадобится для управления кошкой в будущих релизах

HTML-снимки: меню магистра с изученным призывом, бой **до** призыва и **после** призыва, панель управления кошкой, смерть/исчезновение питомца, доступные кнопки атаки/следования/лечения; журнал сетевых ответов серверных действий. До получения этих данных никакая команда питомца не автоматизируется.
