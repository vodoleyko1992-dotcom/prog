# OgameX Suite: one extension for Live, Infinity and (later) Bot

Owner decision (John, 2026-10-30): everything ships as **one** browser extension, «OgameX Suite». OgameX Live and OgameX Infinity are no longer separate extensions. They are now sections of the suite, and every module can be switched on or off on its own. The future «Бот» section (full automation) goes into the same extension. This file replaces DESIGN.md §1.2 (manifest) and the per-extension parts of §1 and §6. Everything else in DESIGN.md, CORE_API.md, DIAG.md and HARNESS.md still applies.

## 1. Layout

```
ogx/
  shared/                          core (single source of truth)
  ogamex-live/modules/<m>/<m>.js   Live module sources       (7: menu planetbar inflight techcost fleetinfo expedition timeline)
  ogamex-infinity/modules/<m>/...  Infinity module sources   (10: panel empire targets spy stats stalk flights fleethelp todo prefs)
  ogamex-bot/modules/<m>/...       Bot module sources (does not exist yet)
  ogamex-suite/                    THE extension (load this directory unpacked)
    manifest.json  loader.js  background.js         integration
    suite/00-suite.js                               section registry (OGX.suite), bot extension point docs
    suite/hub.js                                    module 'suite': the menu entry and the side panel groups
    popup/ options/ icons/                          integration
    shared/  modules/{live,infinity,bot}/           GENERATED by tests/sync.sh (git-ignored copies)
  tools/make-icons.js                               renders icons/*.png from an inline SVG (Playwright)
```

`tests/sync.sh` builds the extension root so it is self-contained. It copies `shared/` and the three module trees into `ogamex-suite/`, deletes the old `ogamex-{live,infinity}/shared` copies, and runs `node --check` on every JS file. It also validates `manifest.json`: MV3, permissions exactly `["storage"]`, a gecko id, every referenced file present (including those referenced by popup.html and options.html), http and https matches on all hosts with gameforge excluded, and the isolated-world script order. That order must be core files in numeric order, then `shared/popup/diag-panel.js`, `suite/00-suite.js`, `suite/hub.js`, the section lists of `00-suite.js` (Live, then Infinity, then Bot), and `loader.js` last.

## 2. Runtime

- **One isolated world, one `window.OGX`, one boot:** `OGX.boot({ ext: 'suite', modules: ['suite', ...live, ...infinity, ...bot], sections, gate, filter })` (`shared/core/00-ogx.js`).
  - `ctx.ext` of a module is its section, so styles keep their ids `ogx-l-*` and `ogx-i-*`. Log lines read `[OGX Suite/<module>]`.
  - The page gets `data-ogx-suite`, plus `data-ogx-live` and `data-ogx-infinity` for each section that has at least one enabled module. Modules use these marks as coexistence signals: for example, Infinity skips its field badges while Live's planet bar runs.
- **Detection:** `OGX.page.isOgx()` runs first on every http(s) page and exits on anything that is not OgameX. `gate()` then applies the optional host allow-list (`*|*|suite.hosts`), after the synchronous snapshot and before anything is stored.
- **Module switches:**
  - Global switches come from the popup (`*|*|suite.modules = { <name>: false }`) and are applied by `filter()`.
  - Per-account switches are the `<name>.enabled` settings. You change them in the panel: Live → «Обзор», or Infinity → «Настройки».
  - A module runs only if both switches are on.
- **Shared resources:**
  - One settings store (`<host>|<pid>|settings`).
  - One diagnostic journal (background IndexedDB `ogx-diag`; export header «Расширение: OgameX Suite 0.1.0», modules listed as `live/<m>` / `infinity/<m>`).
  - One page hook (`window.__ogxHook`) and one bridge.
- **One menu entry:** `OGX.dom.menuOwner = 'ogx-suite-entry'`.
  - Other `menuEntry()` calls (the Live «OgameX Live» entry, the Infinity «Infinity» entry) are built but not attached to the menu.
  - The hub mirrors their badges: refresh-all progress, «!» on self-learning alerts, the hostile fleet count.
- **One side panel:** the panel `'infinity'` is retitled «OgameX Suite» and uses `panel.setGroups()` (new in `07-dom.js`). It has four groups:
  - **Live:** tab «Обзор». It lists the Live modules with their state and per-account switches. It also has the buttons «Окно OgameX Live» (the Live modal: data freshness, refresh-all, server data, Live settings) and «Обновить данные всех планет».
  - **Infinity:** the Infinity tabs, unchanged.
  - **Бот:** a placeholder saying the section is in development.
  - **Логи:** the shared «Логи для разбора» panel.

## 3. Bot extension point

See the header of `ogamex-suite/suite/00-suite.js`. In short:

1. Write `ogx/ogamex-bot/modules/<m>/<m>.js` with `OGX.module(...)`.
2. Add the name to `SECTIONS.bot.modules` and `TITLES`.
3. Add `modules/bot/<m>/<m>.js` to the manifest after the Infinity modules.
4. Add tabs with `OGX.suite.panel().addTab({ group: 'bot', ... })`.

`sync.sh` copies the tree and fails if the manifest and the list disagree. The popup and the «Бот» tab pick the module up automatically.

## 4. Tests

- `tests/suite-e2e.test.js` loads the real `ogamex-suite` in Chromium (or inject mode) against the mock server with the game JS. `T.launch({ ext: 'suite' })` is supported by `tests/lib.js`.
- The module tests (`live-*.test.js`, `infinity-*.test.js`) still test each module in a throw-away extension built by `tests/core-ext.js` from the same core and module sources that the suite ships.
