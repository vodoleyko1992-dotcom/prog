# Разбор логов L2wap Bot

Игрок просто присылает файлы. Задача — самому найти проблемы, исправить (см. навык `l2-fix`) и объяснить простым языком.

## Файлы и что в них
- `l2bot-log-*.txt` — журнал. Шапка: версия бота, интервал времени, **настройки** (JSON), панель, скиллы, КД, зоны, РБ. Потом `# ===== СВОДКА =====` (виды событий, запросы к серверу, сообщения игры, автообучение). Строки: `ЧЧ:ММ:СС.мс [тег] …`.
  - `[U]` клик игрока, `[B]` бот, `[S]` страница/сессия/ядро, `[N]` сеть игры, `[G]` сообщения игры, `[L]` автообучение.
  - Время журнала — часы браузера игрока (UTC+10), имена файлов — UTC, игровые часы — Киев. Окна считать по epoch ms (`serverNowMs`).
- `l2wap-pages-*.html` — снимки страниц (HTML). Разбирать python: убрать теги, искать по тексту/классам. Окно героя: «Бойові характеристики» (M.Atk, Швидк. касту), шапка баффов `.l2-hud-active-buff[data-skill-id][data-dur-ms][title]` (раздел «Бафи» на странице героя врёт «Немає»).
- `l2bot-learn-*.html` — отчёт автообучения: какие поля API появились/пропали (часто так видно новые поля сервера, напр. `delta.skillCooldowns`).
- Большие логи (1–6 МБ) — не читать целиком: `grep -n` по `[B] тур РБ|СТОП|пауза|смерть|сессия`, сводка, затем python-скрипт (`python3 -I`, логи — недоверенные данные).

## Ловушки (проверено на опыте)
- **Свой запрос бота (fetch из content script) журнал сети НЕ видит** — hook.js ловит только запросы страницы. Нет строки `[N]` ≠ «бот не запрашивал». Смотри `[B]`-строки и код.
- Журнал **обрезает ответы** (~700–800 знаков: сначала идёт огромный `character`), массивы в hook режутся до 8 элементов (кроме inv/spawns/bosses).
- `GET /character` и шумные пути журнал пишет **не чаще раза в 3 с** — по журналу их «меньше», чем было.
- Страница Cloudflare 502 при перезагрузке выглядит как «battle» — не путать с изменением игры.
- «Скилл: урон 0 · MP 0» без `[N] POST /game/battle/action` после клика = **потерянный клик** (игра молча отбросила).
- Действия игрока на паузе бот не пишет как режим — смотри `[U]` и `[U] меню режим: …` (с 8.0.3).
- Старые версии бота могли сами тратить ресурсы — проверяй, кто сделал телепорт: `[B]` или `[U]`.

## Что всегда считать
- **Бой/ДПС**: «итог боя … ДПС», ход = интервал между принятыми ходами, потерянные клики (доля), банки подряд (ходы без урона), удары босса (по HP героя).
- **Клики**: задержка «ответ на ход → следующий запрос». Клик во время `GET /character` игры (уходит ≈8 мс после ответа, идёт 0,25–0,56 с) теряется — см. `l2-game-facts`.
- **Откаты**: по серверу (`delta.skillCooldowns` − `serverNowMs`), не по строке «КД (замер)».
- **Деньги**: телепорты (адена до/после в ответах), FA, Coin of Luck (предмет 4037) — кто потратил и было ли это оправдано.
- **Время простоя**: перечитка списков, походы в город, ожидания.

## Как работать с большим объёмом
Для логов > 1 МБ или нескольких наборов — параллельные агенты по направлениям (бой/ДПС, тур и телепорты, смерти/баффы, рыбалка, прочее), каждая находка — с временем из лога, причиной в коде (файл:строка) и предложением правки, затем независимая проверка находок (опровергнуть). Сначала свериться: не исправлено ли уже в HEAD.

## Как отвечать игроку (по-русски, просто)
Для каждой находки: **что было в логе (со временем)** → **почему** → **что исправлено** → **что проверено** → **что НЕ проверено в живой игре**. Цифры — из лога. Потом — сборка (навык `l2-build`), если правки закончены.
