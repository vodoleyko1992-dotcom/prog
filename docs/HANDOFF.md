## 2. Пользователь и как с ним работать

- Пишет по-русски. **Отвечать по-русски, просто, по шагам.** Каждую находку объяснять: что было в логе (со временем), почему, что исправлено, что проверено, что НЕ проверено в живой игре.
- Рабочий цикл: пользователь просто присылает логи (`l2bot-log-*.txt`, `l2wap-pages-*.html`, `l2bot-learn-*.html`, иногда `memory`/`settings` json). Задача — самому найти ошибки и повторы и исправить.
- **Перед каждым коммитом и сборкой — все проверки:** `node tests/run-all.cjs` (на 10.0.11 — 218 PASS), `node --check` всех js, проверка геттеров, на каждое исправление — новый тест. Что не удалось проверить — честно написать.
- **Слияние PR выполняет ведущий агент автоматически; Codex/Astra тоже явно разрешено (14.10)** (указание пользователя 12.10: «слияния жать заколебало»): если все тесты/проверки зелёные, конфликтов нет и PR не трогает то, что ещё обсуждается — влить PR в `claude/l2wap-bot-code-review-t45oon` и написать «влито». Если красное или конфликт — не вливать, сказать, что мешает. Для `merge_pull_request` нужен полный 40-символьный sha.
- **Zip только по явной просьбе** («сборка», «собирай»). Закончили правки — спросить, нужна ли сборка. Версию в manifest/тестах поднимать только при сборке. Стандартно собирается только Chrome-пакет `l2wap-bot-v<версия>.zip`; Firefox-пакет — только по отдельной просьбе. Без суффиксов в имени. В zip не входят `tests/`, `kb/`, `docs/`, `.git`, `.claude`. Сборки складывались в папку проекта `builds/`.
- **Как пользователь обновляет бота:** распаковать новый zip **поверх старой папки** и нажать ↻ в chrome://extensions. (Если распаковать в новую папку — Chrome стирает память бота; так было 4 раза.)
- **Журнал и ведущий (14.10, прямое решение пользователя):** в каждом PR запись в `docs/WORKLOG.md`: дата и время с часовым поясом, автор Codex, номер/ссылка PR, что сделано и что осталось. Все решения пользователя сохраняются в соответствующих разделах этого HANDOFF. Строку «Ведущий» менять только по команде: «работаем на ГПТ» → Codex; «работаем на Клоде» → Claude. Самостоятельно ведущего не переключать.
- **Максимальный аудит (14.10): Astra Ultra** — прямое уточнение пользователя; код и проверка игры выполняются на этой модели. Первый этап `docs/FULL-GAME-ULTRA.md` пользователь счёл недостаточным и потребовал реальные сквозные проверки апгрейда/автоулучшения, автофарма, авторежима/TvT и всех доступных функций. После предварительной сборки 10.0.14 главным приоритетом стал **полный аудит рыбалки**; остальные цепочки остаются в объёме. Живые сценарии завершены, финальные факты и ограничения — `docs/MAX-GAME-AUDIT.md`.
- **Модели по типам задач** (решение 13.10): код и разбор логов — Fable (`claude-fable-5-1`); вопросы без кода — Opus (`claude-opus-5-5`); сборка — Sonnet (`claude-sonnet-5-5`); слежка/опросы — Haiku (`claude-haiku-5-5`). Код, логи и расчёты ДПС Sonnet и Haiku не давать.
- **Админу игры никогда не упоминать бот, скрипт, статистику, выгрузку базы.** Пользователь — зам. лидера клана; иногда просит черновики писем админу (про игровые механики).

## 3. Правила игрока для бота (обязательно)

- **MP не экономим — приоритет ДПС.** Банки MP легко купить. Экономные тактики по умолчанию выключены.
- **Бот стоит, где его оставили** (пока «Автофарм» выключен): бьёт ★-цели квестов, иначе мобов этой локации, **но не ниже героя −5** (иначе не падают FA). Сам никуда не улетает.
- **TvT по умолчанию ВКЛ и важнее всего**, пока идёт (за 3 мин до старта задачи не начинаются, из PvE-боя — на арену).
- «Проверять карту каждые 0 боёв» = никогда (только цепочка «Охотиться дальше»).
- **Чемпионы** (решение 13.10, уточнение 14.10): **оранжевых/жёлтых и красных избегать, синих (и зелёных) бить.** Запрещённый цвет не становится разрешённым ради FA, ресурса, рецепта, квеста или кампании; это правило действует на карте, в катакомбах и цепочке. Если цвет неизвестен, не считать чемпиона синим автоматически. FA с чемпионов: синий 10 %, оранжевый 20 %, красный 60 %, только с мобов не ниже героя −5. Поиск раз в 20 боёв. Красные по умолчанию выключены галкой.
- **Coin of Luck не тратить**, кроме улучшения вещи-цели у кузнеца Маммона. **FA** — только на фулл бафф для РБ/эпиков (наборы `fa-full.js`), не на что-то ещё.
- Заряды строго под надетое оружие (грейд оружия → грейд зарядов; маг. оружие → blessed spiritshot).
- **Магистр (новое решение 14.10):** пользователь попросил изучить гильдию магов и учить новые навыки автоматически **сразу при включении и затем каждый +1 уровень**, с учётом активного класса. Прежнее правило «автомагистр выключен» заменено; новая функция/миграция включения выполняется следующим отдельным PR после аудита. Соблюдать резерв SP, исключения навыков и подтверждать сервером новый ранг; профессию автоматически не менять.
- Спойл: Sweeper не нужен, игра собирает спойл сама.
- **Безопасность:** пароль автологина (storage-ключ `auth`) нигде не появляется — ни в журнале, ни в снимках, ни в экспорте, ни в базовом профиле. **Никакого автоматического решения капчи/антибота.** Маскировку под антибот (случайные задержки ради скрытности) не делаем — пользователь отказал.
- Базовый профиль (`base-profile.json`) применяется только в пустую установку; обновлять по присланным экспортам.

## 4. Доступ к игре из облака

- В настройках облачного окружения пользователь завёл переменные с логином/паролем основного аккаунта и второго аккаунта (`L2WAP_LOGIN`/`L2WAP_PASSWORD`, `L2WAP_LOGIN2`/`L2WAP_PASSWORD2`). **Значения не печатать, не писать в репо, журнал, память.** Если во втором проекте их нет — попросить пользователя добавить их в настройки окружения (не в чат).
- Вход: `POST https://l2wap.com/auth/login` JSON `{login, password}` → `{token}`; дальше `Authorization: Bearer <token>`. Python urllib нужен с браузерным User-Agent, иначе 403. Полезные GET: `/character`, `/game/raid-bosses`, `/game/epic-bosses`, `/game/map/spawns`, `/game/spawn/<id>/info`, `/game/farm-guide`.
- Вход из облака **разрешён всегда**; CoL/FA можно тратить только по делу и писать, сколько ушло. Не точить, не слать письма/передачи, не покупать клановое без просьбы.
- **Антибот:** ≈30 боёв подряд из облака → капча (HTTP 423 `anti_bot_challenge`). При капче — коротко попросить пользователя пройти её самому и ждать.
- **14.10, новое разрешение пользователя:** «не стесняйся заходить в игру и изучать как это работает», затем «я дал задачу на ультрах проверить всю игру, трата FA и coin of luck допустима», модель — **Astra Ultra**. Для этой проверки разрешены живые игровые действия и разумные расходы; фактический ledger обязателен. Это заменяет старый запрет живых боёв в рамках текущей задачи, но **не меняет постоянные правила расходования валют ботом** (раздел 3).
- Живым аккаунтом управляет один исполнитель. Перед действием проверить отсутствие чужого активного боя/изменения revision; свой бой обязательно закрыть, не оставлять очередь действий. При капче остановиться. Не отправлять сообщения/предметы другим игрокам, не портить ценные вещи и не менять сабклассы ради проверки. Урок 12.10: незакрытый облачный бой блокировал рыбалку пользователя 2 ч 42 мин.
- **14.10, вторая фаза:** конкурирующий клиент начал бой, поэтому облачный runtime сразу остановлен. Пользователь затем подтвердил «Бой завершён, бот остановлен — продолжай в игре». Новая точка отсчёта: 97 892 637 адены, 198 CoL, 165 FA, `revision=230610`, Saints Necropolis, вне боя. Промежуточные изменения баланса пользователя не записывать как расходы аудита. Для baseline используется неизменённая распаковка выданного ZIP 10.0.14; текущие исправления тестируются отдельно, без незаявленной пересборки релиза.
