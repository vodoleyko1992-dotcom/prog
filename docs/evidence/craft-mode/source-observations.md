Из развёрнутых панелей DOM:

Шанс всех трёх — 100 %. Активный класс в видимых ответах — `dwarf_maestro`, Create Item 9, maxMp 3085. Разница MP между запросами включает пассивную регенерацию: например, 42 Synthetic Cokes стоят 840 MP, но HUD снизился на 804. Рецепт является источником цены, разницу HUD нельзя целиком считать ценой.

`GET /game/craft/materials` отдаёт `createItemLevel,currentMp,maxMp,canCraftProfession,recipes[]`. В видимом префиксе полностью помещается Braided Hemp: `mpCost:10`, `quantity:1`, ингредиент Stem ×5 при запасе 72669. Его `maxCraftable` равен 308,158,78,92,149,249,288,126 при MP 3085,1585,781,925,1497,2497,2885,1265. Следовательно, `maxCraftable` включает ограничение по MP, даже когда сырья достаточно. При недостаточной MP нулевое значение нельзя автоматически трактовать как нехватку сырья.

Нулевой MP не наблюдался. Во всех видимых префиксах Braided Hemp `lockedReason:null`. Конкретный текст `lockedReason` при нулевой MP этими файлами не установлен. Сообщение «Недостаточно MP» видно в результатах интерфейса после крафта.

## MP-панель

В DOM `/craft.html` есть `#craft-mp-hotbar`, `.l2-craft-mp-slot`, `.l2-craft-mp-choice`, `.l2-craft-mp-edit`. Назначение выполняется клиентским интерфейсом: «Змінити» → слот → тип банки → «Готово». Лог не показывает отдельного API сохранения назначения.

Выбор предлагает:

- Мале MP: +200 MP, 0 штук.
- MP: +500 MP, 493 штуки до использования.
- Велике MP: +2500 MP, 0 штук.

Только ID обычной банки 728 подтверждён отправленными запросами. Использовать ID других типов на основании этого лога нельзя. Первая банка прибавила к отображённому MP 572 из-за регенерации, следующие три — ровно 500.

Ответы `consumable/use` начинаются с `character` и содержат `name,mp,maxMp,l2Profession,classSlots`. Все ответы в TXT обрезаны до 800 символов; `revision` и `inventory` в префикс не вошли. Схема `inventory.stacks[{itemId,qty}]` известна из существующего кода проекта, а не из полного тела этого конкретного ответа. Ошибок `consumable/use` в файле нет.

## Рекомендации для режима

- Отдельная задача «Крафт» должна работать по выбранной конечной очереди, без фоновой охоты; крафтить только на активном классе крафтера и вне боя.
- В dedicated режиме MP можно расходовать на крафт без боевого резерва. Фоновый крафт сохраняет нынешний резерв и не начинает пить банки сам.
- Банку 728 пить только при незавершённом доступном заказе, наличии нужного сырья и недостатке MP. До POST читать свежие `character.revision`, `mp`, `maxMp`, остаток 728; после await повторять guards владельца, героя, класса и режима. Смену режима, Stop и отмену заказа учитывать до расхода.
- При неясном результате банки нужен durable pending, сверка остатков и прежней revision. Не отправлять новую банку с новой revision до разрешения неизвестного исхода.
- Расчёт возможности рецепта должен разделять сырьё и MP. При `maxCraftable:0` и достаточном сырье восстановить MP и перечитать книгу.
- Партии 150 игра принимает. Верхняя граница craftCount не установлена; существующий BATCH 100 безопасно оставить.
- После последней партии не пить следующую банку. При исчерпании сырья или банок явно писать причину ожидания. Автоматические покупки этими наблюдениями не требуются.
- Цепочку Cokes → Synthetic Cokes → Oriharukon можно представить последовательной очередью. Рекурсивное планирование промежуточных материалов — отдельное расширение, оно не подтверждается как существующее поведение.
