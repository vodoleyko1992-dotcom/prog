# L2wap Bot v5.6.5 — этап 3: хранение, кэширование, производительность

Основа: v5.6.4-stage2. Боевой планировщик, логика эпиков, настройки и схема постоянного хранилища сохранены.

## Изменения

1. **Ленивая загрузка `items-il.json` (~1,53 МБ)**. Главный цикл больше не загружает базу без необходимости. База читается по требованию (добыча, инвентарь, автоопределение оружия; также при запросе подсказки ролей из меню). Одновременные обращения объединяются в один `fetch`.
2. **Восстановление загрузки предметов**. Ошибка чтения не запоминается как пустой справочник до конца сессии: новая попытка возможна спустя 30 секунд; программа продолжает работать с доступными данными.
3. **Кэши форумных данных**. Базы ресурсов и рецептов читаются по требованию или при активной цели. В рамках одной страницы параллельные чтения объединены; обновления через меню учитываются в открытых игровых вкладках.
4. **Хранилище `rt`**. При превышении 350 КБ теперь очищаются только восстанавливаемые кэши `forumTp`, `rbForum`, `zoneMobs`, `spawns` и только столько, сколько необходимо. `skills`, `loot`, `questSeen`, `rbSeen` перестали удаляться автоматически. **Важно:** формат `rt` остаётся единым объектом; полноценное разделение хранилища на отдельные подсистемы отложено, чтобы не сломать обмен с меню и изоляцию персонажей.
5. **IndexedDB: журнал и скриншоты**. Удаляются N фактически самых старых записей через cursor, а не диапазон предполагаемых последовательных ID. Исправлен случай разреженных ключей.
6. **Временный отказ IndexedDB**. Незаписанный пакет журнала возвращается в буфер и повторяется через 3 с (максимум 10 000 событий в памяти, чтобы не допустить неограниченного роста при длительном отказе диска). При заполнении буфера самые старые события всё ещё могут быть потеряны.
7. **Жизненный цикл IndexedDB**. При закрытии базы / запросе обновления версии соединение сбрасывается для последующего повторного открытия.

## Проверки

- `node --check` всех JS-файлов — пройден.
- `node tests/stage1.test.js` — пройден.
- `node tests/stage2.test.js` — пройден.
- `node tests/stage3.test.js` — пройден: конкурентные загрузки, задержка повторов после ошибки, кэш ресурсов/рецептов, удаление по разреженным ключам.
- Живая интеграция с Firefox и игровым сервером **не выполнялась**.

## Что сознательно не менялось

- Настройки персонажей, боевые алгоритмы, порядок режимов, платные лимиты и расчёт откатов.
- Схема постоянного состояния (`rt`, `rt@персонаж`, `farmDb`, `recipeDb`) и существующие пользовательские данные.
- Скрипт `skills-il.js` пока загружается при старте content script: его асинхронное выделение затрагивает боевые зависимости и потребует отдельной миграции с полноценным браузерным тестированием.

## Установка

Распаковать архив в новую папку и загрузить `manifest.json` через `about:debugging` (временное расширение). Прежде чем заменять текущую сборку, сохранить экспорт настроек. После первого запуска проверить режимы «Эпики», фарм ресурсов и инвентарь в реальной игре.
