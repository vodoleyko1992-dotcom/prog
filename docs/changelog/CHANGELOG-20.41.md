# L2wap Bot 20.41 — быстрый бой и катакомбы без перезагрузок (Chrome + Firefox)

Сборка Chrome и Firefox по просьбе John: «надо добиться высокой скорости… как сделаешь, потом сборка хром + фаерфокс». Включены PR #318, #319 и #320.

## Скорость (PR #320; жалоба «стал очень медленный», логи 20.10 21:09–22:20)

Что было в логе. Память персонажа выросла до 1,2–1,3 МБ. Каждая её запись в фоне занимала 0,5–1,3 с, и бой эти записи ждал:
- от ответа `battle/start` до первого удара проходило до 4,9 с, подряд ждались 7 записей;
- после каждой победы 0,5–1,5 с уходило на запись итога лимита;
- моб в катакомбах занимал ≈9 с, из них ≈4 с — загрузка новой страницы боя.

Что сделано:
- Бой, баффы, кот, дебаффы, энергия, спойл, цепочка и тур РБ больше не ждут записи памяти. Память вкладки обновляется сразу, а на диск очередь пишет в прежнем порядке.
- Катакомбы:
  - Когда список подземелья однородный, следующий моб берётся штатной кнопкой «Охотиться дальше». Однородный — это ≥3 соседа, ≥80 % подходят по уровню ±1 и нет известного Cancel.
  - Бой продолжается в той же странице, без перезагрузки.
  - Моба выбирает сервер (живой замер: свой `nextHuntSpawnId` он тоже не соблюдает). Если сервер два раза подряд выбрал неподходящего моба, бот снова выбирает сам и переходит на страницу боя, как раньше.
  - Если «Охотиться дальше» не начало бой (игра молча увела на страницу подземелья или ответа нет), бот 30 минут в этом подземелье выбирает мобов сам и пишет об этом строку в журнал. Отказом считается только случай, когда кнопку действительно нажали.
- Итог лимита мобов:
  - Пока до лимита больше 40 мобов, итог пишется без ожидания. Начало следующего боя пишется строго после него.
  - У лимита бот ждёт запись, как раньше: задача снимается ровно на лимите.
  - Если сервер не подтвердил итог, а бот уже ушёл на другую страницу, фон сам засчитывает бой по журналу боя («неточно»), как раньше делала вкладка.
  - Новый бой с тем же номером спавна (цепочка в той же странице) больше не теряет своих убитых, а убитые соседи нового боя не попадают в счёт сессии дважды.
- Статистика обычного боя (награды, ДПС, замеры навыков, счётчики, путь к цели) пишется одним пакетом раз в 8 с или вместе с любой обычной записью. При уходе со страницы остаток дописывается один раз.
- Сброс из меню (↺ сессии, лут, память боя) не откатывается статистикой вкладки — ни ждущей в очереди, ни той, что уже писалась в момент сброса, ни неписаным кэшем памяти боя. Повторный ↺ тех же нулей тоже считается сбросом. Защищена только статистика: намерения покупок, оплаты и маршруты пишутся как раньше. Смена класса (память другого класса из `classStash`) — замена набора, её сброс не отсекает.
- Список подземелья для следующего моба читается уже в начале боя, а не после победы. Если это чтение не удалось, на победе список читается заново. В выбранном вручную подземелье список не читается: там следующий бой даёт штатная цепочка, как раньше.
- Учёт соседей РБ идёт в фоне. Тур РБ не ждёт 4 с отрисовку чужой страницы списка. Убитая цель на открытой странице списка освежает и соседние строки той же страницы, чтобы следующий выбор не шёл к уже убитому РБ. Для VIP подпись «VIP» на странице не стирает бесплатную цену соседа, уже подтверждённую сервером.
- Счёт мобов за сессию в памяти больше не понижается запоздавшей записью вкладки после итога фона (сброс ↺ из меню работает как раньше).
- При уходе вкладки в фон отложенная статистика дописывается сразу. Вкладка в фоне перед каждым продлением замка тоже дописывает её (не дольше 3 с), чтобы видимая вкладка, забравшая замок, не потеряла последние 8 с статистики.
- В строке журнала «размер памяти … КБ» теперь перечислены самые крупные части памяти. По следующему логу будет видно, что разрослось.

Сама память стала меньше и пишется реже:
- Сравнение котов (`petCohorts`) хранило в каждой строке весь снимок героя — снаряжение, умения и ключ JSON-строкой: ≈11 КБ × 100 строк ≈ 1,1 МБ из 1,3 МБ памяти. Теперь строка короткая (только то, что показывает меню, и счётчики), ключ — короткий хэш, хранятся 40 самых свежих строк: 1114 КБ → 18 КБ. Старые строки ужимаются при загрузке вкладки со счётчиками без потерь. Вкладка без замка откладывает только само ужатие и делает его после замка по свежей памяти того героя, который сейчас активен.
- После каждого ответа `GET /character` бот заново писал всю память: хранилище Chrome отдаёт ключи по алфавиту, и слоты классов не совпадали строкой. Теперь сравниваются значения.
- Запасы клика, причина ожидания навыков и минутная копия статуса пишутся отложенным пакетом.
- Итог в настоящем MV3 на цепочке катакомб: «Охотиться дальше» в той же странице — 0 обычных записей вкладки на моба (было 1), остаётся только итог лимита в фоне.
- Фон больше не слушает `storage.onChanged`. Раньше каждая запись памяти 1,3 МБ доставлялась ему целиком дважды (старое и новое значение) в том же потоке, что пишет память. Цикл записи 420–470 мс → 310–340 мс, мелкая операция хранилища сразу после записи 180–200 мс → ≈1 мс. Значок «ON», отмена восстановления сторожа и новый отсчёт сторожа при запуске теперь делают сами команды Старт/Стоп/горячая клавиша/сторож; прямые остановки модулей и импорт памяти просят фон перерисовать значок. Раз в минуту сторож сверяет значок с фактом («!» капчи остаётся). После «Очистить журнал» объём снимков считается заново с нуля.
- Рыбалка: после исхода заброса первая Pumping/Reeling и следующий заброс больше не ждут записи снятия отметки заброса. Новый заброс по-прежнему ждёт своей записи намерения.

Замер на модели сервера (настоящий MV3, задержка ответа 400 мс, память 1,3 МБ): цикл «удар → следующий удар» в катакомбах сократился с 2,6 с до ≈1,4–1,6 с. С ужатой памятью каждая запись ещё в 3–4 раза короче (около 0,1 с вместо 0,4–0,5 с).

Не сделано. Оставшийся предел интервала между ударами — собственный запрос игры GET /character после каждого действия, ≈0,3–0,45 с. Сервер принимает следующий удар сразу после ответа (живой замер на герое). Убрать этот запрос можно только вмешательством в ответ игры, а такое решение ждёт John. В этой сборке `hook.js` не менялся.

## Из PR #318 / #319 (вечер 20.10)

- Закупка при «сумка полна» (HTTP 500 `inventory_full`) больше не держит бота 3+ мин в магазине.
- ДПС по РБ и прогноз тура считаются по своему классу. Саб Bounty Hunter больше не берёт замер основного Warlock.
- Тур РБ:
  - не летит к уже убитым РБ по старому списку — перед переходом один JSON-GET страницы цели;
  - открытая страница списка освежает все свои строки.
- Native Whirlwind / Wild Sweep снова дают урон из журнала боя. Испорченные средние сброшены один раз.
- «КД сервера» в выгрузке: поля КД лежат в `data.cd`.
- Маммон в простое тура РБ узнаёт цену кузнеца.

## Мелкое
- Анализ сумки Маммона хранит время самого чтения сумки. Раньше пересчёт после смены цели мог сдвинуть его на 1 мс (браузерная проверка падала через раз).

## Не проверено

- Реальный прирост фарма нужно измерить по полному логу после обновления.
- Firefox ZIP не подписан. Android не проверялся.
- Если замок бота перехватит видимая вкладка, пока прежняя ещё видна, статистика последних ≤8 с (опыт, адена, лут, замеры) из прежней вкладки не дописывается. Лимиты мобов это не задевает: их ведёт фон.
- Сосед РБ, умерший за ≈0,5–1 с до отхода бота от РБ, может не попасть в дневной счёт мобов.
