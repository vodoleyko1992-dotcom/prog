# 20.83 (в работе, не собрано)

Правки после 20.82. Версия в manifest и ZIP не менялись: сборка — только по отдельной просьбе.

- **Rebirth без лишних серверных сверок** (John 30.10: «какие-то серверные сверки, лаги», журнал 30.10 12:03). В журнале моб похода занимал ≈3,0 с, сам бой — ≈0,5 с. Около секунды уходило на повторную проверку героя и похода в начале каждого следующего боя (сначала GET /character, затем бой и поход), хотя те же проверки прошли за секунду до этого, перед своим «Охотиться дальше». Ещё около секунды занимали проверки после победы и лишняя полная запись памяти (≈500 КБ) ради метки `via`. Теперь следующий моб своего продолжения допускается одним свежим GET живого боя. Он одноразовый, действует не дольше 15 с, только для обычного моба, при том же походе, герое, классе, уровне и при своей квитанции продолжения. Во всех остальных случаях, а также для чемпиона и РБ, проверка полная, как прежде. Метка `via` больше не переписывает память на каждом мобе. Оценка по журналу: ≈0,6–0,9 с экономии на моба. Живой замер не проводился.
- **Потерянный ответ «старт боя»** (12:02:44: ответ start пришёл с ошибкой 500 через 7 с, а сервер уже открыл следующего моба). Бот 33 с повторял «жду повторной серверной сверки», пока страницу не обновили. Теперь, если свежий сервер показывает, что свой герой уже в бою этого же похода, бот бесплатно открывает каталог, а оттуда возвращается в этот бой. Новые next/start не нажимаются, квитанция не снимается.
- **Причина сбоя в журнале.** 11:22–11:36 бот 14 минут показывал «серверная сверка не ответила», пока страницу не обновили вручную. Журнал не показал, что именно не ответило. Теперь причина пишется в журнал раз в минуту, а текст сетевых ошибок (адреса и токены) в журнал не попадает.

PR #460/#461 из 20.82 к этим задержкам не относятся.
