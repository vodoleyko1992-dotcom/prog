# 20.47 — восстановление чтения при медленных ответах API

22.10.2026, по вопросу «как можно решить данную проблему?» и последующему выбору «Собрать Chrome 20.47». Только основной Chrome; Lite и основной Firefox не пересобираются. PR #349.

После сетевого сбоя в журнале 02:20 ответы API занимали 10–23 с вместо примерно 0,4 с. При повторной сверке сумки бот всё равно ограничивал чтение персонажа шестью секундами. Теперь первая попытка остаётся быстрой, а после неудачи повтор в том же контексте получает до 25 с. Успех возвращает обычные 6 с. Корректный ответ через 14 с принимается без нового Start.

Дополнительно исправлена отдельно воспроизведённая слабость GET: таймер снимался после заголовков, до чтения тела. Нативный AbortSignal.timeout теперь ограничивает и JSON/text; зависший поток освобождает INV_READ и не публикует неполную сумку. Присланный TXT именно сценарий незавершённого тела не доказывает.

POST, проверки героя/класса/ревизии/владельца/Stop и защита неизвестных расходов сохранены. Перезагрузки боя и фонового сторожа не менялись. Настройки и базовый профиль прежние; Spoil с пикой, голем на фарме и плановая карта через 100 побед из 20.46 включены.

Это улучшает восстановление при медленных ответах, но не исправляет сам сервер или соединение. При полностью недоступной сети повторное чтение может ждать до 25 с.

Проверки кода: новый Node-тест 24/24 PASS, baseline17 PASS/7 FAIL; полный набор 598 PASS/0 FAIL, envcheck34/34, syntax/bash/diff PASS. Настоящий Chrome156 с native fetch/Response и точными функциями content.js:4/4 PASS — незавершённый body,6→25→6, Stop, смена владельца; actor/env управляемые, это не полный игровой MV3-сценарий. Живую игру и полный исторический browser-run не запускали.
