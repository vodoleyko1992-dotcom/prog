## Исправление

- После подтверждённой записи намерения и непосредственно перед native-кликом рыбалка ставит маркер попытки в `sessionStorage` вкладки. Hook синхронно дописывает точную `expectedRevision` **до** настоящего fetch/XHR send. Маркер содержит только героя, время попытки/отправки и revision.
- После reload фабрика восстанавливает revision по квитанции только при точном совпадении героя, попытки и корректных времён. Это работает при отключённых журнале/сетевой записи и потерянном `netStart`, без ручного «Старт».
- Точный запрос из позднего ответа может дополнить потерянное начало запроса только после общей проверки сетевого контекста и при прежних герое/lease/времени начала.
- Если во время чтения исторического журнала уже пришла revision из сети, старый ответ журнала не перезаписывает её и новые поля намерения. Сообщение об успешном восстановлении появляется только после подтверждённого сохранения.
- Сама сверка результата прежняя: согласованные серверные снимки, исходная revision, запрет слепого повтора, консервативный учёт неизвестного заброса. Подтверждённый следующий заброс проходит обычные лимиты. Stop, другая задача, lease, TvT, платежи и антибот продолжают ограничивать действия.

Затронуты `hook.js`, `content.js`, `modules/fishing.js`, новые Node/MV3-проверки и browser-runner. В изолированном старом тесте цели добавлена зависимость новой функции; прежние проверки исходов сохранены. Правки меню из PR #265 интегрированы отдельно, при конфликте runner сохранены оба браузерных файла.

## Проверки и ограничения

- Новые Node-сценарии: 66 для hook и 20 для восстановления/гонок. До исправления соответствующие группы давали 10 FAIL / 56 PASS и 9 FAIL / 11 PASS; после — 86 PASS.
- Actual MV3: включённый движок → native cast → reload → продолжение без Start; потерянный netStart при `rec=false`; медленный ответ 8442 мс; Stop; снятая задача. MAIN/ISOLATED действительно используют одну квитанцию. Проверяется количество принятых запросов, расход наживки и предел двух забросов.
- Дополнительно: жизненный цикл Start/Pause/Resume/reload/две вкладки/Stop, дневные лимиты и учёт рыбы, завершённая цель. Все API локальные, живой аккаунт и публичный сервер не открывались.
- Итог полного Node-прогона, браузерных файлов, синтаксиса и envcheck указан в WORKLOG.

Новая квитанция не восстанавливает задним числом старый pending. Для уже существующей записи без revision остаётся прежнее восстановление по однозначному сетевому журналу. Если подтверждение отсутствует, повреждено или неоднозначно, ручное ожидание сохраняется: текущая revision сервера не подставляется вместо исходной. Fetch с телом только внутри объекта `Request`, без `init.body`, остаётся ограничением прежнего перехватчика; в предоставленном журнале JSON-тело native-запроса доступно.
