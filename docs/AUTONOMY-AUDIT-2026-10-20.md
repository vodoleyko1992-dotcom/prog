# Инженерный аудит ежедневной автономности — 20.10.2026

Работу выполнила команда Codex: координатор, архитектор автономности, аналитик логики, инженер отказоустойчивости, аналитик управления, скептик и независимый проверяющий. Проверяющие воспроизводили конкретные контрпримеры; согласие команды не считалось доказательством.

## Область и исходное состояние

Исходный checkout `a4c6e50` отставал от сервера. Аудит и исправления начаты на `ce931a8` (PR #291), затем объединены с `522218a` (готовая сборка 20.27, PR #292). Версию и ZIP этот аудит не меняет. Источник запуска, тестируемое распакованное расширение и установленная пользователем копия — разные объекты: версию последней удалённо подтвердить нельзя.

Это расширение MV3: `background.js` сериализует управление, аренду вкладки и записи; `content.js` выполняет диспетчер; `hook.js` наблюдает реальные запросы; `engine-core.js` задаёт выбор задач/лимиты/очередь; `modules/*` исполняют действия; `popup.js` редактирует профиль. `chrome.storage.local` содержит общий и отдельные для героя cfg/rt; журнал и снимки ограничены IndexedDB (20 000 событий, 1 000 снимков, 50 МБ разметки). Замок распространяется на вкладки одного профиля расширения, не на другой браузер/устройство.

Серверные сутки определяет GET `/game/time`, затем полный score `/game/daily-quests`. Живой сервер сообщил `Europe/Kyiv`, день `20261020`; местная дата оператора UTC+10 не используется как игровой сброс. Это уже реализовано PR #291. Дневные лимиты и разовая серия различаются: следующая дата не означает автоматический сброс разовой цели.

До аудита уже существовали сохранение прогресса, квитанции платежей, дневная сверка, watchdog, повторное получение аренды, восстановление после reload, выбор нескольких задач и ручные Stop/Resume. Ни один из этих механизмов сам по себе не доказывает ежедневную автономность. Найдены сценарии, где они теряли записи, блокировали независимую работу или принимали неподтверждённый результат за успех.

## Что изменилось после независимого возражения

- Первого guard «recover завершён» было недостаточно: скептик поставил следующую запись в microtask, уронил её и показал потерю. Добавлена проверка непустой очереди перед release.
- Проверки `on=false` и имени героя было недостаточно: старый release проходил после нового Start→Stop с тем же epoch. Добавлена привязка к запуску; отдельно проверен вход через горячую клавишу.
- Первоначальный daily gate чрезмерно расширял старую политику. Независимый проверяющий нашёл альтернативные входы РБ и поздний auto→tasks. Итоговый scope сохранён по существующим правилам: дневной cap относится к auto/cat/fish; явно выбранные farm/raid/quests/epic не объявлены новыми квотируемыми режимами.
- Пустой DOM рыбалки признан недостаточным основанием для переключения. Отложенная задача требует согласованного серверного target:null и героя; неизвестный результат не разрешает альтернативную платную операцию.
- HTTP 2xx перестал считаться достаточным для перечисленных некорректных тел. Произвольный непустой JSON не объявлен доказанным успехом всех игровых endpoint: это отдельный оставшийся контракт.
- Первоначально упавший тест raid quota оказался смешением реального и тестового времени, а не потерей счётчика в runtime. Эквивалентная правка уже пришла в PR #292; взята версия upstream. Тест server-day также использует согласованные часы fixture.

## Модель состояния и восстановления

| Состояние / событие | Действие и подтверждение | Предел / дальнейший путь |
|---|---|---|
| Start / новый игровой день | Получить актуальные время и полный дневной score, сохранить stamp героя/дня/запуска | При ошибке retry 15 с; новые ограниченные действия закрыты, независимые службы доступны |
| Продолжение после reload | Получить аренду, загрузить rt своего героя, сверить фактический экран/квитанции | Успешный stamp того же дня/запуска сохраняется; unfinished/pending не обнуляется |
| Новая добыча | Проверить выбранную задачу, разрешения, дневной лимит, владельца; сохранить intent перед действием | При изменении контекста прекратить продолжение; подтверждённый результат считать один раз |
| Ответ потерян / тело не подтверждает результат | Сохранить pending и перечитать фактический результат/запас | Тайм-аут не означает отказ. Новое списание не разрешено по одному отсутствию ответа |
| Экран улова не соответствует серверу | Сверка target/revision, ограниченное обновление страницы | ≤3 reload /10 мин; затем GET с паузой, неизвестный исход сохраняется |
| Рыбалка временно недоступна, улова точно нет | Записать причину и until, выбрать другую разрешённую задачу | 5–300 с по прежнему backoff; новая команда/изменённый контекст отменяют ожидание |
| Длительная пауза | Показать причину/срок, проверять изменение управления | Новая команда прерывает idle за один такт; честное ожидание API не считается полезным прогрессом |
| Stop с несохранённым результатом | Прекратить действия, дописать очередь, затем release | Ошибка записи сохраняет очередь до следующего тика; OFF не удерживает аренду бесконечно |
| Смена героя / владельца | Отменить поздние продолжения и неподтверждённую чужую очередь | Не переносить состояние A в B; новый владелец сверяет сервер |
| Суточная квота выполнена | Сохранить результат, ожидать следующего серверного дня | Новый день запускает свежую сверку. Разовая завершённая серия сама не превращается в ежедневную |

Инварианты: один владелец в профиле; никакой чужой записи после смены героя; неизвестный платёж не равен неисполненному; достигнутые квоты не обнуляются при reload; Stop отменяет поздние действия; восстановление не создаёт новый бюджет reload на каждом шаге; активность не засчитывается как подтверждённый результат.

## Живые проверки героя

Пользователь сначала предоставил героя для контролируемых проверок, затем на уточнение границ ответил «все можно». Координатор был единственным исполнителем живых действий команды; остальные браузерные стенды использовали локальные HTTPS. Неизвестная версия расширения на других устройствах не объявлялась проверенной; локальная аренда их не охватывает.

1. **Read-only запуск, reload, Stop:** 2026-10-19 21:53:55–21:54:36 UTC, 41,127 с. Настоящая игра и расширение, явный пустой список задач. Серверные дата/квоты прочитаны, stamp сохранён после reload. Герой вне боя, HP/MP/адена/CoL неизменны, ошибок страницы нет. Автоматические POST нативной страницы (enter-map/login-claim/player-interaction) блокировались стендом; это не полноценный игровой цикл. До этого такой же прогон имел ошибочную проверку «никаких попыток POST»: источник запросов установлен как загрузка native при OFF, критерий исправлен без разрешения игровых мутаций.
2. **Один рабочий заброс с перезагрузкой во время улова:** 21:57:27–21:58:04 UTC, 36,767 с всего браузерного сеанса; действие cast в21:57:49, результат подтверждён в21:58:01. До запуска GET подтвердил свободного героя, удочку +10, изученные навыки, имеющееся время и наживку. В отдельном профиле: fishMaxCasts=1, dailyFishLimit=1 при исходном серверном счёте0, никаких покупок/заточки/разделки, лимит 300 с. Бот выбрал обычную наживку, выключил заряды, сделал **1 cast**, перезагружен при `target=White Fish`, продолжил Pumping/Reeling и **поймал White Fish**. После: casts=1, caught=1, dailyQuota.fish=1, pending=null, active=false, серверный target=null. Обычная наживка 9111→9110, хорошая105 неизменна, адена509727814 и CoL180 неизменны. К моменту последнего снимка ранее оплаченное время уменьшилось на14,808с (65070385→65055577мс); окончание серверного окна расхода после Stop отдельно не измерялось. Дополнительных забросов, блокировок запроса страховкой и ошибок страницы нет.
3. После Stop координатор вернул прежнюю выбранную хорошую наживку и включённые заряды двумя подтверждёнными настройками с expectedRevision. Итоговая revision373560, герой вне боя, target=null; покупки не выполнялись. Контекст браузера закрыт. Фоновое ночное наблюдение не оставлено работающим.

Один завершённый улов подтверждает этот путь восстановления. Полных продуктивных суточных циклов — **0**; реальный переход суток в испытании не ожидался. Ускоренная серверная полночь проверена отдельно на стенде и не засчитана как ещё один живой день.

Диагностика: [живой read-only](evidence/AUTONOMY-2026-10-20/live-readonly.json), [заброс и reload](evidence/AUTONOMY-2026-10-20/live-fishing-one.json), [возврат настройки снасти](evidence/AUTONOMY-2026-10-20/live-fishing-restored.json), [runtime SHA256](evidence/AUTONOMY-2026-10-20/runtime-sha256.json). Токены, пароли, cookie и сырые приватные ответы не сохранялись. [Архивный сценарий](evidence/AUTONOMY-2026-10-20/live-fishing-one.cjs) требует явного opt-in, [условия воспроизведения](evidence/AUTONOMY-2026-10-20/README.txt) описывают ограничения повторного запуска.

## Первоначальная настройка и участие пользователя

При уже установленном расширении, вошедшем герое и подходящих сохранённых ограничениях: открыть «Обзор» → нажать «На месте», «Автофарм», «Рыбалка» или «Катакомбы». Это одно решение о главной работе и один запускающий клик после открытия меню, без обязательных текстовых полей. Быстрая кнопка сохраняет разрешённые фоновые задачи; она не означает «только эта задача». Для точного списка — «Выбранные задачи → Изменить», нужные галки, Start. Пустой явный список означает ожидание.

В коде 251 default-параметр и 206 ключей базового профиля, но они не являются обязательными для заполнения. Доступны 14 задач; автозаточка по прежнему решению пользователя скрыта и выключена. Перепроектирование всего интерфейса в этом аудите не выполнено. Новых технических настроек не добавлено.

| Решение пользователя | Почему нельзя выбрать автоматически | Фактический путь |
|---|---|---|
| Цель и допустимые занятия | Бот не знает намерения игрока | Быстрый запуск или явный список; после настройки обычный Start/Resume |
| Расходы и ограничения ресурсов | Наличие адены не является разрешением её потратить | Принять или изменить сохранённые разрешения/лимиты. Автопокупка времени рыбалки по defaults выключена |
| Авторизация | Бот не может вывести логин/пароль из цели | Уже открытая сессия; для автовхода два поля подключения, сохранённые пользователем |
| Допустимое время суток | Не выводится из игровых событий или часового пояса | Общего пользовательского расписания пока нет. Stop не планирует автоматический Start |

Для новой базы обычные мобы имеют дневной cap 8000, рыба — диапазон 1511–1564; фактически действует сохранённый профиль. Эти значения не являются новым разрешением тратить ресурсы при испытании. На сочетании defaults+base-profile «только фарм на месте» через точный список требует снять семь фоновых/прочих галок, то есть 9 кликов с открытием списка и Start. Этот расчёт относится к указанной конфигурации, а не к любой существующей установке.

| Ручная зависимость | Что автоматизировано / что остаётся |
|---|---|
| Временная ошибка сети или daily API | Повторное чтение, сохранение pending, продолжение независимых служб; вмешательство в проверенных сценариях не нужно |
| Устаревший DOM рыбалки | Ограниченные reload и серверная сверка; недоказанный исход не закрывается наугад |
| Ошибка сохранения настройки | Видимая ошибка, безопасный повтор и блокировка Start до сохранения; исправление выбора остаётся явным действием |
| Закончилась оплаченная рыбалка | При разрешённой покупке — существующий путь; иначе пауза и другие выбранные задачи. Новое разрешение расхода принимает пользователь |
| Завершена разовая серия | Нужна новая цель или выбор дневного режима; завершённая серия не обнуляется произвольно |
| Намеренный Stop/Pause | Только явный Start/Resume; самовключение после команды пользователя недопустимо |
| Капча/отсутствующий доступ | Конкретное действие пользователя; обход не реализуется |
| Закрыт браузер или последняя игровая вкладка | Требуется запуск среды; watchdog не является внешним сервисом запуска компьютера |
| Обновление установленного расширения | Исходники опубликованы отдельно от установленного пакета; выпуск ZIP производится по отдельному запросу проекта |

## Границы результата и следующие шаги

1. Браузер и устройство должны работать. Расширение не запускает выключенный компьютер и не является внешним круглосуточным сервисом. Общего планировщика пользовательских временных окон в этом изменении нет; серверный сброс суток и расписание TvT не заменяют его.
2. Несколько меню одного героя могут одновременно изменить целиком autoTasks и потерять одну из независимых правок. Исправлена очередь внутри меню и запуск после сохранения, но межоконный read-modify-write требует отдельной атомарной операции фона `{key,enabled}`. Не считать решённым.
3. Подтверждённый живой улов на другой странице, когда fish не выбрана, автоматически не доводится. Новая ограниченная добыча безопасно ждёт; следующий шаг — отдельный проверенный маршрут завершения чужого/ручного улова.
4. **Остаточный риск подтверждения оплаты:** произвольный непустой JSON без `error`/`ok:false` по-прежнему может получить `applied` без доказанной покупки. Нужны конкретные схемы результата endpoint и отрицательные контрактные тесты. На живом сервере такой ответ не наблюдался; исправление некорректных/пустых тел не закрывает этот класс. Это приоритетный следующий аудит платёжных контрактов, до расширения разрешённых автоматических расходов.
5. Капча, отсутствующий вход, конфликт целей/расходов и постоянный отказ хранилища требуют конкретного вмешательства. Капча не обходится. Другой профиль/устройство не включён в локальную аренду.
6. Полноценные рабочие часы, запуск браузера после перезагрузки ОС, удобный единый мастер первоначальной настройки и многодневный продуктивный прогон остаются самостоятельными этапами. Требуется определить допустимое время/расходы и наблюдать реальную установленную сборку; простой героя не засчитывать как автономный рабочий цикл.
