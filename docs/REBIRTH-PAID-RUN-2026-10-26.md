Источник — присланные John TXT/learn/pages 26.10.2026 11:53, установленная 20.66. Разбор статический, скрипты вложений не выполнялись, живой сервер не открывался. Время ниже — из журнала игрока.

## Подтверждённая ошибка

Игрок вручную вошёл в Easy в 21:51:22.199: `POST /game/rebirth-raids/start`, difficulty1, HTTP200. Интерфейс показывает цену два ключа с участника; в снимках до и после 20→18 ключей. Это единственный подтверждённый новый вход. Дальнейшие запросы `GET /game/rebirth-raids/next?after=…` и `POST /game/battle/start` продолжают тот же run.

В 21:52:04.675 игрок включает бота на экране победы над мобом19. В 21:52:05.691 вручную нажимает «Охотиться дальше»; следующий моб20 открыт сервером в 21:52:06.328. В 21:52:06.679 бот выполняет «плановая проверка целей — раз в50боёв», затем `leave`200 в21:52:06.985. К этому моменту новый бой уже активен, HP2546/7128. В21:52:09.677 игрок снова ставит паузу.

Все186 HTTP в этом отрезке получили200. Это ошибка маршрута и отмены старого обработчика победы. Новый вход и предыдущие бои были ручными; они не доказывают автоматическое прохождение подземелья.

`mobfarm.dungeonBattle()` признаёт только `sdms_`. Расширять его на Rebirth нельзя: существующие `catNext/catGo` предназначены для другого подземелья. Для нового `rebirth_raid_` обычные `mapDue` и поиски карты неприменимы во время продолжения активного run.

Есть второй дефект: `combat.mobName()` берёт часть заголовка до первого `·`. Заголовок «Rebirth · Akaste Succubus Turen · ур.21» превращается в «Rebirth». Разные виды смешиваются в истории HP/статистике, а точное имя не совпадает с серверным `Rebirth · Akaste Succubus Turen`.

## Контракт, который виден в данных

- `GET /game/rebirth-raids?view=instance`: `activeRun.id`, `phase=mobs`, `mobKillTarget=300`, `mobKills=22`, `participantCharacterIds` содержит ID собственного героя. Явного поля owner в полном объекте run нет. `partyId=null` в этом одиночном заходе.
- Spawn имеет семейство `rebirth_raid_<run.id>_…`. Идентификатор следующего моба нельзя получать прибавлением единицы: после AoE сервер пропускает убитых, например16→19 и21→23.
- `GET /game/rebirth-raids/next?after=<completedSpawn>` возвращает `{phase:'mobs',spawnId:…}`. Ответ платного `/start` имеет другую форму `{run,nextSpawnId}`.
- Продолжение выполняет нативная кнопка `#battle-victory-hunt`. Она использует собственный обработчик игры; дополнительный прямой запрос `/next` от бота не требуется.
- На странице instance строки `.l2-rraid-fight` не имеют сохранённых spawn/href/data атрибутов, а `mobTargets` обрезан экспортом. Соответствие строк и целей не восстановлено. Фазы чемпиона/логова/выбораРБ/завершения не наблюдались.

## Реализация

`combat.mobName` сохраняет весь префикс до суффикса уровня. Без такого суффикса обычный заголовок сохраняет прежний разбор; полный префикс Rebirth остаётся частью имени. Общий старый `hpMin['rebirth']` не переносится на конкретные виды. Явные признаки чемпиона продолжают обрабатываться прежними фильтрами.

`mobfarm.nextFight` отдельно распознаёт Rebirth-бой до обычных `mapDue`, городских служб и sdms-planner. Снимок победы захватывается ещё до первого ожидания TvT; смена страницы, владельца, класса, поколения, battleInfo, заголовка или DOM-кнопки отменяет старое продолжение. Уже активный новый бой возвращается обычному боевому циклу без выхода на карту.

Перед нативным продолжением проверяются свежие `/character` и `/game/rebirth-raids?view=instance`: свой герой/класс/слот/ревизия, отсутствие текущего боя, Rebirth-этап, точное соответствие run префиксу завершённого spawn, участие героя, `phase=mobs` и незавершённая квота run. Идентификатор завершённого моба берётся из текущих метаданных/контекста; старый URL цепочки не подменяет его. Лимит охоты, TvT, Stop и аренда вкладки сохраняют действие.

После проверок используется только живая `#battle-victory-hunt`. Прямой `/next` помощник не вызывает, идентификаторы не вычисляет. Синхронная отметка в sessionStorage сохраняется до клика: неизвестный исход не допускает повторное нажатие, включая reload. Неясные данные дают ожидание с паузой15с, сетевой отказ —60с, без запасного ухода на карту.

Перед кликом также учитывается незавершённый запрос текущего игрока к Rebirth-next или боевому start/hunt/action. Первое ревью выявило слишком широкий запрет по всем запросам; он сужен до этих маршрутов. Chat/events/character GET не удерживают продолжение.
