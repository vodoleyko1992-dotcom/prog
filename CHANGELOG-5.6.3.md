# L2wap Bot v5.6.3 — Этап 1: устойчивость

Основа: v5.6.2-fixed. Все пользовательские настройки и справочники сохранены.

## Изменения

1. **Одна рабочая вкладка.** Захват, продление и освобождение блокировки сериализованы в background.js. Запросы из разных вкладок не могут одновременно успешно захватить одну блокировку. При передаче управления старая вкладка прекращает действия по сигналу изменения замка.
2. **Изоляция персонажей.** Смена персонажа выполняется через фоновую сериализованную операцию; когда бот включён, только владелец блокировки может менять общие `rt/cfg`. Существующие ключи `rt@ник` и `cfg@ник` сохранены для совместимости. При передаче блокировки новая вкладка заново загружает общие данные.
3. **Сторож зависаний.** Ожидающие вкладки больше не посылают пульс сторожу. Перед перезагрузкой сторож проверяет, что отслеживаемая вкладка — текущий владелец блокировки.
4. **Отступление с эпика.** Пока не подтверждён уход со страницы боя, боевой цикл не отправляет новые атаки. По истечении 12 секунд без подтверждения попытка признаётся неудачной, повторное отступление для эпика блокируется на час, бой обрабатывается без ложного успеха.
5. **Автообучение API.** Ошибочные ответы HTTP 400 и успешные ответы учитываются в отдельных группах. Для боевых ответов различаются обычные, delta и итоговые сообщения. Ложные сообщения «пропали поля» на `skill_cooldown` устранены.
6. **Сохранение.** При сбое записи в локальное хранилище добавлена повторная попытка через 3 секунды.

## Проверено

- `node --check` всех JS-файлов.
- `node tests/stage1.test.js`: конкурентный захват, переход владельца, защита смены персонажа, автообучение, структурные проверки.
- Целостность ZIP.

## Ограничения

Это проверенная локально, но **не испытанная в живой игре** сборка. Изоляция состояния рассчитана на существующую модель одного активного персонажа и хранение снимков `rt@ник`/`cfg@ник`; полной миграции хранилища на отдельные независимые ключи пока нет. Возможны поздние действия, начатые непосредственно до смены вкладки — для полного устранения нужен следующий этап с управляемой очередью действий.

Следующий этап: планировщик боевых навыков и серверные cooldown, бюджет расходников и повторных телепортов, оценка боёв.
